Case study

Notifications that never reached field workers

MWM Clevest, notification-sending service

The incident

Several customers reported that a notification reached only about 60 to 70 field workers. Many employees never received it.

Root cause

The service runs on a 90-minute schedule and sent only 7 messages per run. The notification queue resets each day and refills with a large new batch. For customers with high volumes, a day of runs could not get through the batch at 7 messages at a time.

The fix

Raising the fixed number for everyone would have put load on customers who were already performing well. Instead I made the batch size a setting in the application configuration.

messages per run = configured value, or 7 when the value is null or empty

The result

Existing customers see no change in behavior. High-volume customers can raise their batch size to clear the whole day's queue.
