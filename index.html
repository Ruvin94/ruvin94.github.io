Notifications that never reached field workers

MWM Clevest, notification-sending service

The incident

Several customers reported that a notification reached only about 60 to 70 field workers. Many employees never received it.

Root cause

The service runs on a 90-minute schedule and sent only 7 messages per run. The notification queue resets each day and refills with a large new batch. For customers with high volumes, a day of runs could not get through the batch at 7 messages at a time.

The fix

Raising the fixed number for everyone would have put load on customers who were already performing well. Instead I made the batch size a setting in the application configuration.

messages per run = configured value, or 7 when the value is null or empty

The result

Existing customers see no change in behavior. High-volume customers can raise their batch size to clear the whole day's queue.

Faster order custom field updates

MWM Clevest, SQL performance

The problem

Updating custom fields on orders was slow. When something like this is slow, the usual suspect is database health, but in this case the database was not the cause.

Root cause

The SQL query loaded fields it never used and made the classic N+1 mistake: one extra query for every record instead of one query for all of them.

The fix

I rewrote the query to read only the fields the update needs and to fetch the related data in a single round trip instead of one trip per record.

The result

Order custom field updates run faster without any change to the database itself.

Emails that failed only when an image was added

MWM Clevest, third-party email service

The problem

MWM sends template-based custom emails through a third-party service. Adding an image to a template is optional and customers rarely use it. One customer did, and their emails failed.

Investigation

Because the image feature is so rarely used, there was no obvious lead. After hours of debugging through the code, I found that our code was sending valid requests and the third-party service itself was failing whenever an image was included.

Resolution

I informed the customer, then took the problem to the provider with evidence: the Postman calls I used to reproduce it and the return codes the service sent back.
